# 可视化教程视频

一句话出片：给链接、给网页、给截图、给录屏，都行。全流程一条命令，中间不碰代码。

**三类输入 → 同一套产出**

| 你给什么 | 它怎么取画面 |
|---|---|
| 文章链接（公众号/网页） | 抓正文 + 下载配图，自动分镜 |
| 网页/文档地址 | 自动打开、点击、滚动，真实关键截图 + 动态取景 |
| 截图 / 录屏 | 直接入片，自动配版式与说明卡 |

**适用**：产品发布稿、功能说明、操作文档、官网介绍、教程类长文、录制好的操作流程。
**不适用**：纯观点文（没画面可截）、需要真人出镜、要伪造产品界面才能讲清的内容。

三种用法，都是一条命令：

```bash
# ① 文章链接：抓正文 + 配图 → 全自动
TV_PROJECT=~/my-video python3 scripts/build_all.py --url https://mp.weixin.qq.com/s/xxxx

# ② 网页/文档：自己在 project.json 配 capture.url，脚本去截图
TV_PROJECT=~/my-video python3 scripts/build_all.py --only capture

# 半自动：已写好 project.json（要精细控制文案时）
TV_PROJECT=~/my-video python3 scripts/build_all.py
```

产出：**成片 MP4（含章节）+ 3:4 封面 + SRT/VTT/ASS 字幕 + 8 个备选标题**。

## 本机教程执行优先规则（2026-10-29）

涉及本人的软件实操教程，以 references/real-operation.md 为执行标准。以下旧版通用模板中的1.35倍速、横屏双栏、0.1秒片头、动态素材优先及轻录屏描述均不适用于本机教程：默认统一 **1.5倍速**、正文 1920×1080（16:9）、封面 1080×1440（3:4）、0.1 秒封面、真实关键截图动态取景。不得执行旧录屏入口或模拟操作动画。既有素材渲染仍可复用。宣传数字、福利金额与CTA须有本次已确认依据，不自动套用旧示例。正文截图中的界面颜色保持真实，不为红白风格改写软件界面。

## 流水线

```
fetch 抓文章+配图 → storyboard 自动分镜写旁白 → capture 网页取画面 → assets 素材加工
→ annotate 圈重点 → cover 封面 → cards 说明卡 → voice 配音 → manifest 时间轴
→ audio 音轨 → subs 字幕 → ┬ html 渲染页 → frames 逐帧 → patch 嵌动图 → mux 合成 → titles 标题
                            └ render_fast 快通道（ffmpeg 直出，跳过逐帧截浏览器）
```

**两条渲染通道，按产量选**（2026-10-29 加）：

| 通道 | 单条耗时（30 秒片） | 用在哪 |
|---|---|---|
| `html → frames → mux`（慢） | 约 75 秒 | 单条精修、要逐字弹性字幕 / 叠化转场 |
| `render_fast.py`（快） | 约 30 秒，4 并发可到 12 秒 | **批量铺量，矩阵号一律走这条** |

前一版需要人做「抓图、拆分镜、写旁白、拼素材」，现在都进流水线了。**脚本出 70 分草稿，人手润色到 90 分**——润色重点永远是这三处：封面大字、每段右侧文案、旁白口语化。

**段数不写死，按正文体量算**：一段旁白约 28 字（≈5 秒），531 字的稿子会自动切 15 段，不是固定 10 段。
所以 3 分钟、5 分钟的稿子直接喂进去就行，切完就多几段，不用改代码。要强制段数就配 `"storyboard": {"target_scenes": 24}`。
**纯文字稿（一张图都没有）也能跑**：所有场景自动退化成说明卡，不会崩。

## 环境要求

| 依赖 | 说明 |
|---|---|
| Python 3.10+ | 需要 `playwright`、`Pillow`（`pip install playwright pillow`） |
| ffmpeg / ffprobe | 必须带 `libx264`、`aac`；**不需要 libass**（字幕画在页面里） |
| 浏览器 | 系统 Chrome 优先，没有就 Edge，再没有才用 Playwright 自带内核 |
| VoiceBox | 本机 `127.0.0.1:17493`（配音用；不用配音可跳过 voice 步骤） |

**🔴 开工第一件事：确认解释器（这台机器踩过）**

系统默认的 `python3` 不一定是装了 playwright 的那个。2026-10-29 实测：
这台 Mac 上默认 `python3` 是 WorkBuddy 自带的 3.13（**没有 playwright**），
真正能跑的是 `/opt/homebrew/bin/python3.11`。直接 `python3 build_all.py` 会报 `No module named 'playwright'`。

```bash
# 一次找对：列出所有带 playwright 的解释器
for p in python3 /opt/homebrew/bin/python3.11 /opt/homebrew/bin/python3.13 \
         /usr/bin/python3 ~/.venv*/bin/python3; do
  $p -c "import playwright" 2>/dev/null && echo "OK  $p"
done
```

找到后整套命令都用它。**别急着 pip install** —— 先确认是不是只是选错了解释器。


三平台都跑得通，脚本会自己找路径：

- **ffmpeg**：PATH → Homebrew → `C:\ffmpeg\bin` → winget/scoop/choco 常见位置
- **VoiceBox 音频目录**：macOS `~/Library/Application Support/sh.voicebox.app/generations`；
  Windows `%APPDATA%\sh.voicebox.app\generations`；Linux `~/.local/share/sh.voicebox.app/generations`。
  探测不到就在 `project.json` 写 `voice.data_dir`，或设环境变量 `VOICEBOX_DATA_DIR`
- **中文字体**：PingFang / 微软雅黑 / Noto CJK 自动切换（封面、说明卡、ASS 字幕都是）

## 全自动模式怎么跑

```bash
mkdir my-video && cd my-video
TV_PROJECT=$PWD python3 <skill>/scripts/build_all.py --url <文章链接>
```

它会依次：下载正文与配图 → 按小标题切场景（默认 10 段）→ 逐段改写成口播短句 → 自动配对截图（没图的段自动生成说明卡）→ 跑完整条片。

跑完先看三份文件，再决定要不要重跑：

| 文件 | 看什么 |
|---|---|
| `article.json` | 正文抓全了吗、图够不够、有没有内嵌视频（视频下不了，要人工补截图） |
| `project.json` | 场景顺序、每段旁白、封面文案 |
| `delivery/titles.md` | 8 个备选标题 + 四维打分 + Top3 |

要调，就改 `project.json` 后 `--from assets`（改图/文案）或 `--from voice`（改旁白）续跑，不用从头来。

## 盘点 / 清单类选题（2026-10-30 踩坑后补）

「必装的 N 个 skill」「N 个神器」这类选题，最容易犯的不是做不好，是**漏**。

**四条硬规则**

1. **第一位永远是自研主力**：讲「做视频必装」，第一个必须是 `可视化教程视频`（我们自己的产线）。
   把它当成「工具本身」排除在外是错的——它才是最该被装上的那个。除非用户当次明确说「只讲市面上现成的」。
2. **声称 N 个，画面里就必须有 N 个**：写完 scenes 数一遍条目，`len(清单) == 标题里的 N`，
   少一个就是事故；多一个也别硬塞。
3. **每个条目必须有专属画面**：不许同一张图复用两次，也不许用「同类示意」凑数——
   观众看得出哪几个是真的、哪几个是糊弄的。
4. **别把「技能市场搜索结果」直接当清单**：搜索只返回市场上有的，
   自研的、本地装好但没上架的、用户自己的，全都搜不到。搜索结果是**素材**，不是**答案**。

5. **必须给「从哪进」和「搜什么」**（2026-10-30 袁总退回）：只念名字等于没教。
   每条至少要有：**入口路径**（左上角「专家·技能·连接器」→ 技能页）+ **精确搜索词**（`口播视频全流程`，不是「口播那个」）+ **生效条件**（装完开新会话）。
   一份说不出路径的清单，对观众价值是零。

**入口路径（照抄，别写错）**

```
WorkBuddy 左上角 →「专家·技能·连接器」→ 切到「技能」页 → 顶部搜索框打名字 → 卡片点「安装」→ 开新会话生效
```

**交付前自检四问**
- 我列的第一个，是不是用户自己最常用的那个？
- 标题说 6 个，画面里是不是 6 个、每个都有独立画面？
- 这 6 个里有几个是我为了凑数从搜索结果里顺手拿的？
- **每个都写清「从哪进、搜什么、装完怎么生效」了吗？**

原来的错误链：拿到「视频 skill」搜索结果 → 顺着 6 条结果填进分镜 → 全程没回头问一句
「用户自己的主力 skill 去哪了」。搜索是手段，选题才是目的。

## 找方案：GitHub 是第二个超级外挂（2026-10-30 定）

做视频要临时解决一个问题时（某种转场、某个动效、某类剪辑），**先去 GitHub 搜，别自己硬造**。
SkillHub 的技能是打包好的；GitHub 上有大量「agent skill 仓库」，质量和更新速度往往更好。

**三条检索式**（按命中率排序）

| 目的 | 查询 |
|---|---|
| 找现成 skill 仓库 | `claude skills video sort:stars` / `topic:claude-skills video` |
| 找具体能力 | `remotion <要做的效果>` / `ffmpeg <要做的效果> skill` |
| 找中文垂类 | `短剧 skills`、`口播 skill`、`视频剪辑 agent` |

**筛选用四个硬条件**：① star 数（>1k 才看，>3k 优先）② 近 30 天有更新 ③ 仓库里有 `SKILL.md` 或 `skills/` 目录 ④ README 有真实产出截图/样片，不是只有口号。

**装法**：仓库带 `SKILL.md` 的，整包放进 `~/.workbuddy/skills/<名字>/`，重启会话即生效；
 marketplace 里能搜到的直接 `search_and_install_skills` 装。

**踩过的坑**：**大仓库别直接 clone**。用 `curl -s https://api.github.com/repos/<owner>/<repo>` 先看 `size`（单位 KB）：

- `< 20MB` → 可以 `git clone --depth 1`
- `20–80MB` → 只下 zip 里的 `skills/` 子目录，或 `--filter=blob:none --sparse`
- `> 100MB` → 别 clone，读 README + 挑单个 SKILL.md 用 `raw.githubusercontent.com` 直接取

实测 `video-shotcraft` 201MB、`herk-edit-kit` 460MB，直接 clone 会被系统 SIGTERM 掐掉。

## 真实实操取证（网页、WorkBuddy 与其他桌面应用）

收到“你自己操作、截图、做教程”时，由当前 Agent 实际操作目标应用；不能只运行视频渲染脚本，也不能把截图任务转交用户。先读 [实操取证闭环](references/real-operation.md)，实际查看本次可用工具，再执行。工具名字以当前环境为准，文档中的示例不是已经存在的接口。

两种模式分别处理：已有图文素材继续沿用现有成片流程；需要自己演示时，先完成真实操作和证据核验，再写旁白、建立 project.json 并进入渲染流程。渲染流水线本身不会替代应用操作。

禁止新录屏、连续采集屏幕、先录后抽帧、调用花录；禁止 capture_ops.py 的模拟光标、点击涟漪、逐字输入时间轴。禁止 record_screen.py。动态感只来自已保存真实截图的一层推近、拉远或平移及红白解释图。用户已提供的视频可作为已有素材使用，但不能据此恢复录屏。

桌面 App 可以通过实际可用的桌面操控工具逐步操作和截图；能力或权限不足时报告具体缺口，保留已完成证据，不能声称桌面 App 天生只能由用户操作。网页优先复用已登录目标标签；不要为了截图另开没有登录态的空浏览器。禁止复制浏览器凭证或修改网络设置。

保存截图到项目 assets/raw/，裁切隐私后的入片副本到 assets/screenshots/。使用已有 ingest_shots.py 时先查看 --help；不照抄旧机器坐标。项目配置设置 `"mode":"self-operated"`，并填写 evidence.json；执行 `python3 scripts/check_evidence.py` 通过后再运行成片步骤。机械检查不替代看图与结果核验。

### 真实操作截图怎么变成动效（守「禁止录屏」红线）

本机规则禁止连续录屏、禁止 `record_screen.py`、禁止先录后抽帧。想要画面会动，用**多张真实操作截图**拼：

1. Agent 实际操作一步 → 存一张截图到 `assets/raw/`（**单步截图，不是连续采集**）
2. 同一场景攒 8–15 张，放 `cua/frames/`
3. `frames_to_clip.py --dir cua/frames --name step1 --fps 2 --crop 0,380,2940,1532` → `clips/step1.mp4`
4. scene 上加 `"clip": {"file": "clips/step1.mp4"}`

**判断动效真假**：相邻两帧必须有肉眼可见变化（翻页、展开、切换）。
点一下没反应的动作用来凑帧，等于一串静止图，观众一眼看穿——据实保留静态 + 推拉更稳。

**绝对禁止**：AI 生成「看起来像界面」的图当截图；把说明卡说成产品界面；用占位图冒充真实数据。

### 圈重点：给截图画线框

纯图观众不知道看哪，必须圈。配 `annotations` 段，比例坐标（0–1），脚本自动画框 + 编号：

```json
"annotations": {
  "assets/raw/01.png": {
    "out": "assets/screenshots/settings-annotated.png",
    "color": "#C7352D", "width": 6, "radius": 16,
    "boxes": [
      {"box": [0.017, 0.573, 0.142, 0.606], "badge": "1"},
      {"box": [0.256, 0.495, 0.973, 0.940], "badge": "2", "label": "浏览器操控"}
    ],
    "arrow": {"from": [0.10, 0.60], "to": [0.40, 0.52]}
  }
}
```

- `badge` 会自动浮在框角**外侧**，不挡内容；`label` 是贴在框右上角的小标签
- **封面上不要底部图例**（只留两行字）；标注编号只出现在正文截图里
- 封面截图一律 `shot_fit: "contain"`，整张缩进画面，**不许 `cover` 裁切**（裁了就只显示半张）

**量坐标的笨办法但最快**：把截图缩到 1085 宽，叠 100px 网格，用视觉看一眼就知道框该从哪到哪，再除以宽高得比例。

## 出片后自动同步到本地视频中心（2026-10-29 加）

成片不留在项目目录里等人来拿，**`build_all.py` 最后一步自动推进他的「汇芯视频中心」**
（`http://127.0.0.1:8765/#lib`，本地 Flask 服务，会扫盘建库）。

- 脚本：`scripts/push_library.py`
- 做什么：按片库命名规范把成片和封面复制过去 → `POST /api/rescan` 让它刷新
  - `<标题>-YYYYMMDD.mp4`
  - `<标题>-YYYYMMDD-封面.jpg`（脚本自动清同名旧版，不会出现两个日期）
- 落到哪个目录：先问 `/api/output_dirs`，按 `lab → koubo → kepu → promo` 顺序取第一个存在的；
  也可 `--dir ~/Desktop/xxx` 指定
- 服务没起也不报错：会提示「重扫失败，手动点刷新片库」，文件已经复制好了

单独跑：

```bash
TV_PROJECT=$PWD python3 scripts/push_library.py --dry     # 看会复制到哪
TV_PROJECT=$PWD python3 scripts/push_library.py
```

## project.json 字段

只有 `title`、`slug`、`scenes` 是必需的，其余不写就用默认值。

### 顶层

```json
{
  "title": "WorkBuddy 远程控制",
  "slug": "workbuddy-remote",
  "language": "zh",
  "series": "WORKBUDDY · 远程控制",
  "date": "2026-10-29",
  "source": "官方发布稿 · mp.weixin.qq.com/s/xxxx",
  "canvas": {"width": 1920, "height": 1080, "fps": 30},
  "lead": 0.35, "tail": 0.75
}
```

`lead` 是每段旁白前面的留白，`tail` 是后面的留白；两者决定气口，别调太小。

### voice

```json
"voice": {
  "profile_name": "袁六伟",
  "engine": null,
  "model_size": "1.7B",
  "speed": 1.5,
  "loudnorm": "I=-14:TP=-1.0:LRA=9",
  "data_dir": ""
}
```

- `engine` 留 `null` 最省事：脚本读音色自带的 `default_engine`，报 400 会自动换引擎重试
- `speed` 用 ffmpeg `atempo` 变速，**音调不变**
- **教程固定 1.5x，这是唯一值**。实测对照（克隆音「袁六伟」）：

  | 设定 | 实测 | 相当于 |
  |---|---|---|
  | 1.35x（旧，已废弃） | 4.64 汉字/秒（278 字/分） | 比新闻联播略快，比抖音口播慢 15–20%，**已弃用** |
  | **1.5x（当前唯一标准）** | **约 5.2–5.4 音节/秒（约 320 字/分）** | **抖音口播主流节奏** |
  | 1.65x 以上 | — | 克隆音开始发紧、有机械感，不建议 |

  **不许降速、不许回退 1.35x，即便知识类长视频也一样。** 1.5x 是袁总 2026-10-30 拍板的硬标准：
  短视频时代节奏慢就掉完播。要留思考时间，只能靠**素材展示时长**和**气口（lead/tail）**，绝不靠改语速。
- **改语速不用重新合成**：首次生成时原始音（未变速）会存到 `voice/raw/<场景id>.wav`，
  下次只改 `speed` 再跑，脚本直接复用原始音重跑 `atempo`，8 段几秒钟完成。
  文本改了会自动识别（比对 hash）重新合成；换了音色/模型要加 `--resynth` 强制重来。
- `loudnorm` 统一响度，成片之间不会忽大忽小（`I=-14` 比源音频响约 6dB）

### 真实界面操作截图（强制优先，配合 `Mac应用截图操控`）

教程类视频**优先用真界面操作截图，其次才是设计卡片**。要「真点一下再截」时，走这条链路：

1. 编译 CGEvent 工具（绕过 System Events 的 -10004）：`click.swift` / `key.swift` / `listwin.swift` → `swiftc -O`
2. `listwin` 找到目标窗口的 **WID 与逻辑坐标**（窗口原点单位是点，OCR 给的是 2× 像素，除以 2 再叠加原点）
3. `screencapture -x -o -l <WID>` 只截该窗口（不受遮挡、不泄露桌面）
4. `scripts/ocr.swift` 定位文字坐标，别靠肉眼估
5. `click x y` 真点 → 再截一张，对比状态变化

**已实测（2026-10-30）**：WorkBuddy 的「三个模式」不在输入框底栏，而在 **输入框「+」→ 模式** 子菜单里
（默认模式 / 计划 Plan / 仅问答 Ask）。做模式类选题直接截这个菜单，不要画卡片冒充。

⚠️ 点击前先 `open -a WorkBuddy` 确保前台，否则坐标会打在其他 App 上；操作完按 Esc 关菜单、恢复原模式。

**信息密集的界面必须加线条引导**（2026-10-30 袁总要求）：截图里文字多时，**不要靠放大/推拉**——
放大就丢了位置感，观众不知道你点在界面的哪儿。正确做法是：

1. 截图保持**全景**（整窗或带侧栏的裁切），让人看到自己在哪个位置
2. **红框**圈住目标行 + **红色编号圆标（①②③）** + **短箭头**指进框
3. 说明文字交给右侧面板，**不要把标签叠在截图上**（会压住菜单、让画面发灰）
4. 场景里 `zoom` 固定 **1.0**、`target` 铺满，**禁止用 zoom/target 推拉界面镜头**（推拉只留给纯数据/文字特写）
5. 侧栏任务名、聊天内容涉及隐私时，**局部高斯模糊**（只模糊侧栏和菜单上方，菜单本身要清晰）

另外：截图区在 16:9 画面里只占左侧约 60%，菜单原图别超过 ~1000px 宽，否则右边会被面板挡住。

- 但 1080×1440 在手机上会被放大显示，发虚 → **默认 `"dpr": 2`，实际输出 2160×2880（仍是 3:4）**，缩到任何尺寸都清晰

## 快渲染通道 + 变体种子（批量铺量用，2026-10-29 加）

```bash
TV_PROJECT=$PWD python3 render_fast.py                 # 读 sop.json + voice/full.wav
TV_PROJECT=$PWD python3 render_fast.py --jobs 4        # 4 个场景并行
TV_PROJECT=$PWD python3 render_fast.py --seed 7        # 出第 7 号变体
TV_PROJECT=$PWD python3 render_fast.py --seed 7 --out delivery/v07.mp4
```

**为什么快**：慢通道是 Playwright 逐帧截浏览器（约 15 帧/秒，30 秒片子要 75 秒）；
快通道是「PIL 画静态叠加层 + ffmpeg 一次 filter_complex 合成」，浏览器完全不参与成片渲染。
实测 15.6 秒片子 15 秒出片，4 并发下线性下降。

**拿什么换的**（知道就行，别当 bug 报）：
字幕整句淡入而非逐字弹性缩放；场景硬切而非叠化；高亮框静态描边而非脉冲。
单条精修仍可走慢通道，两条通道产物都是 1920×1080 / 30fps。

### 变体种子：一条内容裂成几十个「看着不一样」的版本

矩阵号最大的风险是几十个号发同一条，被判搬运。`--seed N` 用同一份 sop 派生确定性差异，
**同一个 seed 永远出同一版**，可以复现、可以去重、可以按账号固定分配。

| 维度 | 变化范围 | 作用 |
|---|---|---|
| 推拉幅度 | ×0.88 ~ ×1.22 | 画面运动节奏不同 |
| 推拉方向 | 居中／上／下／左／右 | 同一张图的运动路径不同 |
| 字幕字号 | 36 / 38 / 40 | 版式密度不同 |
| 字幕高度 | 底 36 / 40 / 44 / 48 / 52 | 构图不同 |
| 画面位移 | ±1.5% | 裁切框不同，肉眼几乎无感但指纹变了 |
| BGM | `assets/bgm/` 里按 seed 挑一首，压到 -22dB 垫在人声下 | 音频指纹不同 |

**要真防查重，只靠渲染变体不够**，必须叠上创作层的差异：不同封面、不同开场钩子、
不同片段顺序、不同旁白措辞。渲染变体是「同一稿的不同拍法」，不是「不同的稿」。

**BGM 目录**：项目根下建 `assets/bgm/`，丢几首 mp3 进去，变体会自动轮换；
人声走 `voice/full.wav`，混音时 BGM 自动压到 -22dB。

## 设计规范（别改，这是验证过的）

**🔴 节奏硬规则（时长与快慢）**

- **不设时长上限，内容是唯一标准。** 别再为「压进一分钟」砍掉有效内容 —— 脚本可能是 40 秒，也可能是 3 分钟、5 分钟。
  段数按内容切（一屏一动作），该几段就几段，不设 8 段上限。
- **决定时长的是信息量，不是指标**：一段讲清一件事就 4–6 秒；有 15 个步骤就是 15 段。宁可长，不要挤。
- **教程语速全程恒定在 1.5x（唯一值，不许降）**，不要一段快一段慢；「快慢」靠**素材展示时长**调，不靠改语速。
  长视频最容易犯的错是「内容多了就偷偷加速」，绝对不行。
- **落音后必须量语速**：`字/秒 = 音节块数 / 音频时长`（汉字 1、英文词 1、数字 1）。
  正常应落在 5.0–5.6 音节/秒；某段低于 4.3 说明 TTS 把停顿拖长了，重合成该段或缩短文本。
- **素材该快快**：表格、列表、长截图这类信息密度高的画面，动效推到 **2–3 倍速**（推拉幅度大、位移快），观众扫一眼就够，不要慢慢磨。
- **讲解该慢慢**：步骤类画面（点哪里、开关在哪）留够 4–6 秒，给观众照做的时间。
- 单段低于 4 秒会看不清，高于 7 秒会拖沓；表格式场景压到 4–6 秒。
- **长片的节奏靠「换画面」，不靠「加速」**：3 分钟以上的片子，每 5–8 秒必须有画面变化，
  且每 30–40 秒插一个「进度锚点」（第几步 / 还剩几步），否则完播率崩。
- 判断标准：观众不需要暂停就能跟上每一步；停下来想想「这段是不是可以不讲」，而不是「能不能再压两秒」。

**真实截图优先**：关键入口、实际输入、执行后状态、可见结果必须有真实证据；不按截图数量凑动作。一个稳定可读的结果比一串无效变化更有价值。静态截图可做有目的的一层运镜，不冒充连续操作录像。

**🔴 结尾 CTA 硬规则（所有 WorkBuddy 相关视频一律带）**

- 片尾最后一段必须是互动引导，话术固定：**「评论区回复 666 送你 2693 元的一人公司福利包」**
- 口播 + 画面**都要有**：口播念一遍，画面出一张「评论区回复 666」卡（`cards` 里加 `card-cta`，`type: steps`）
- 不能只做口播不给画面，也不能只出画面不念
- 若客户或活动改了金额/暗号，只改数字和关键词，句式不动

**🔴 结构硬规则：先给结果，再讲步骤（优先级最高）**

观众不会因为「步骤齐全」看完，只会因为「我也想要这个结果」才愿意跟着做。所以顺序永远是：

| 位置 | 内容 | 时长 |
|---|---|---|
| 0–3 秒（黄金三秒） | **直接甩结果 / 利益**：「788 条数据，我全程没点一次鼠标」 | 1 段 |
| 3–8 秒 | 结果再来一个（换个平台/换个场景），坐实「这不是巧合」 | 1 段 |
| 8 秒之后 | 娓娓道来：第 1 步 → 第 2 步 → 第 3 步 → 第 4 步 | 每步 1 段 |
| 倒数第二段 | 同样的办法还能干什么（扩想象） | 1 段 |
| 最后一段 | CTA | 1 段 |

**开头绝不能是「今天我们来讲怎么安装」**——那是说明书，不是短视频。

**🔴 教程必须覆盖「下指令」这一步**

90% 的教程视频只讲了「装在哪」，漏掉最有价值的一步：**装完之后要怎么跟它说话**。这一步必须单独成段，画面上给出指令原文：

- **四要素**：打开哪个网站 / 搜什么关键词 / 抓哪些字段 / 要什么格式
- **给一句真实原话**，不要只讲抽象公式：「打开小红书，搜 workbuddy，抓前 50 条标题和点赞，做成表」
- **有真实指令截图就用截图**；没有就用说明卡（`type: list`）把原话打出来 —— **不许 P 图伪造聊天界面**
- 讲完指令，紧跟一段「它自己怎么干」的过程画面（进度、条数变化、建表），证明指令真的生效

**🔴 小白标准（写稿时逐段对照）**

每一段都要能让一个没用过的人照着做出来，检查三点：

1. **点哪里** —— 具体到「设置 → 智能体 → 拉到最下面」，不说「去设置里找找」
2. **看到什么** —— 「会亮一个绿点」「会弹窗要授权」，让他知道自己做对了没
3. **完了什么样** —— 这一步做完，界面上应该出现什么

一段只讲一个动作；一句话超过 26 字就拆开。宁可多一段，不要一句话塞两个动作。

**🔴 封面四件套（2026-10-30 第 6 版定稿）**

封面就四样东西，多一样都是负担：

1. **深空底** —— 近黑蓝渐变 + 蓝光 + 细星点，铺满四边
2. **红胶囊** —— 顶部 `WorkBuddy实操`，白字，圆角 999（品牌词就藏这儿，省下一整行给钩子）
3. **两行大字** —— 第一行白、第二行柠檬金，思源黑体 900，占画幅 37% 左右
4. **矢量图形** —— 下半部分一张纯 SVG（发光星球／节点网络／数据卡片…），**不用任何截图**

- **其他所有文字一律删掉**：kicker、序号、副标、标签块、底条、网址、署名 —— 一个都不留
- **代码已经硬拦截**：`make_cover.py` 把 `title_lines` 压到 2 行、其余文字槽位整块剔除，
  `make_storyboard.py` 生成草稿时直接不给这些字段。文档说得再好也没用，得脚本拦得住
- 每行 `white-space:nowrap` 不许浏览器自己折行 —— 一折就变三行，等于白改
- 字号**先自动放大到撑满宽度再回收**，短文案（3 字）也能压满画面，不用手调 `title_size`
- **必须等字体加载完再量字号**：`@font-face` 是异步的，提前量会拿回退字体算出偏大的字号，
  字会溢出画幅（已踩，模板里 `document.fonts.ready` 之后再算）

**🔴 矢量图形怎么选（`cover.motif`）**

图形一律是 `templates/motifs/` 下的纯 SVG，**不贴产品截图**。选型按题材对号：

| motif | 长什么样 | 用在哪 |
|---|---|---|
| `orbit`（默认） | 蓝色星球 + 金色双轨道环 + 光点 | 通用、没明确题材时的兜底，最百搭 |
| `nodes` | 金色核心 + 六个蓝色卫星节点连线 | 多智能体、多账号、自动化、并行任务 |
| `grid` | 三层透视卡片 + 金色表头 + 勾选徽章 | 出表、抓数据、报表、清单类 |
| `play` | 播放圆盘 + 时间线轨道 + 刻度 | 剪辑、视频、生成、播放类 |

- 想加新图形：往 `templates/motifs/` 丢一个 `<motif>.svg`（**viewBox 用 `0 0 640 420`**，元素要铺满这个框），
  自动就被识别，配置里写 `"motif": "文件名"`
- 项目专用的图形放 `<项目>/assets/motifs/xxx.svg`，同名优先于内置
- 图形统一配色：金色渐变 `#FFF4B8→#FFCE45→#E08A0B`，蓝色 `#66A3FF→#1E4FC4`，发光靠 `feGaussianBlur`
- 老项目要退回贴截图：`"art": "shot"` + `"shot": "assets/screenshots/xx.png"`（不推荐，等于回到第 5 版）

**🔴 封面满幅**

- 画布 1080×1440，**深空底一路铺到四边**，不许黑边/灰边/白边、不许 letterbox
- 截图必须**横向铺满**（左右贴到画布内边距），不许缩成小卡
- 主标题字号 ≥ 画布宽度的 18%（1080 → ≥195px）；缩到 160×213 仍要一眼读清
- 导出 `cover-3x4.jpg` + `.png` 两份；同步片库用 `-封面.jpg`；`"dpr": 2` → 2160×2880
- **每条视频都必须单独出一张 3:4 封面**（`--only cover` 随时可重跑）；`cover_from_frame.py` 只是「从成片裁帧撑满」的备选，不作默认

**🔴 封面硬规则（优先级最高）**

- **凡是 WorkBuddy 相关教程，封面必须出现「WorkBuddy」** —— 它是高权流量词，也是平台搜得到你的唯一入口
- **进红胶囊也算数**：`badge` 里有 workbuddy 时，`make_cover.py` 不再强占一行补品牌词，两行全给钩子
- 胶囊被关掉（`"badge": false`）时，仍按老规则补一行 `WorkBuddy`，`enforce_brand: false` 才能破例
- 同理，视频标题也必须带 WorkBuddy（见「标题规范」）

**🔴 封面必须满出血、不许留白（2026-10-29 袁总当场退回重做）**

封面在视频号里是**一格格缩略图**并排显示的。浅底 + 内缩的「白卡片」放进列表就是**一圈白边**，
看起来像没做完；同一行里别人的封面是整块实色，你就被压死了。

- **背景必须铺到四边**：底色/大图/渐变一路到 0 像素边界，**四边任何一个像素都不许是白或浅米色**
- **标题吃掉画面宽度**：主标题字号以「撑满 92% 宽」为准，靠字号压场，不靠留白显高级
- 自检方法：把封面缩到 **160×213**，第一眼应该是「整块深色 + 一块亮字 + 底部一条亮图」；
  看到「一圈浅色边 + 中间一坨小字」就是不合格
- **暗底不等于死黑**：四角要被蓝光晕开，交付前看一眼四角是不是纯黑一片 —— 是的话把 `.sky` 的蓝光半径调大
- `cover-swiss.html` 只留给「浅色文档风」场合，**短视频封面别用**——它的米白边就是被退回来的原因

**封面（视频号 · cover-videohao.html，默认）**

- 下半部分：`.art` 区居中放内联 SVG（`flex:1`，`min-height:440px`），图形不吃满宽就往上缩

## 已知坑（都踩过）

1. **HyperFrames 在这台机器上跑不起来** —— `npx hyperframes render` 卡在启动 Chrome，7 分钟零帧；`check` 被 SIGTERM。本 skill 用自建 Playwright 逐帧渲染，**别切回去**。
2. **ffmpeg 没有 libass 也能出片** —— 字幕画在渲染页里，随帧输出，不依赖 `ass`/`subtitles` 滤镜。
3. **Playwright 与缓存内核版本不匹配** —— 一律用系统浏览器（Chrome → Edge → 内置）。
4. **帧目录残留会让成片变长** —— 重渲染帧数变少时旧帧还在。渲染后按 `总时长×fps` 截断，用 `os.remove` 循环删（`rm -rf` 会被安全机制拦）。
5. **VoiceBox preset 音色用 `qwen_custom_voice`，克隆音色用 `qwen`** —— 混用报 400。现在的脚本自己读 `default_engine` 并自动重试，不用手配。
6. **VoiceBox 状态接口返回 SSE** —— `GET /generate/{id}/status` 返回 `data: {...}`，要剥前缀。
7. **Windows 上 VoiceBox 目录不是 macOS 那个** —— 用 `voice.data_dir` 或 `VOICEBOX_DATA_DIR` 显式指定最稳。
8. **Windows 控制台默认 GBK** —— `build_all.py` 已注入 `PYTHONUTF8=1`，单独跑脚本时请设 `set PYTHONUTF8=1`。
9. **不要给 target 估坐标** —— 估出来的框会套在空白处，比不加框更难看。用颜色检测或在原图上量准比例。
10. **旁白讲到哪，画面就要有什么** —— 只放 logo 卡讲「以前要上传文件」属于裸讲，观众 get 不到。
11. **自动分镜只是草稿** —— 它按标点切句、按顺序配图，不懂内容重点。开场对比卡、场景取舍、封面标题这三处必须人改。
12. **旧录屏路径已停用；真实操作可能被权限挡住** —— `osascript` 控制 Chrome、`System Events` 发按键都报 `-10004 权限违例`；`cua_scroll`/`cua_execute` 可能 `provider invocation timed out`。能用的是 `dom_cua_keypress`（返回 ok），但**飞书多维表格这类 canvas 表格不吃 DOM 键盘事件**，按了不动。真滚动要满足其一：给 WorkBuddy 开「辅助功能 + 自动化」权限，或 CUA 服务正常。
13. **降级方案：推拉动图** —— 拿不到真滚动就 `kenburns_clip.py` 把表格截图做成缓慢推近/平移（`--zoom 1.18 --dir down`），视觉上「活」起来，比纯静态强很多。别用假 UI 动画冒充真操作。
14. **内嵌视频抓不下来** —— 报告素材缺口，可用真实关键截图解释；不得新录屏替代。
15. **PIL 画符号会出豆腐块，而且不报错** —— macOS PingFang 里 `✓`(U+2713)、`✔`(U+2714) 都缺字形，
    渲染成空心方框，做完一整批才发现。判断方法不能看「有没有像素」——豆腐块也有像素，
    要拿私用区 `U+E000` 当基准比对 mask。已封装成 `common.pil_mark()` / `common.pil_char_ok()`，
    **清单符号一律走它**，缺字形会自动降级到 `√ ● ○ → ▶`。
16. **ffmpeg 直出和逐帧截图的画质不一样** —— 直出走 `zoompan` 时输入图要先放大到 2×
    （`scale=2400:1350`）再缩回 1200×675，否则推近会发虚；且必须 `setsar=1`，不然某些播放器拉变形。
