# 实操分镜与讲解衔接

按观众要学会的动作组织镜头，而非按素材文件顺序拼接。核心步骤须有入口、关键动作/输入、变化后结果的真实证据；统一写入项目根目录 `steps.json`（见[steps-schema](steps-schema.md)），再映射到 `camera.json`。缺失关键证据时补取对应真实操作截图，不录屏或从新录像抽帧，不用介绍页、“完成”提示或 AI 生成界面替代。

## 前后截图默认

- **每个核心操作默认成对取证**：`shots.before`（动作前完整入口/上下文）＋`shots.after`（动作后可见变化）。
- **模态框、下拉菜单、确认对话框、二级面板**另存 `shots.extra`（至少一张能看清选项或文案的图）。
- 一张图可服务多句旁白，但不把 before/after 合成一张糊弄；缺一对就阻塞旁白定稿与正式渲染。
- 推近默认对准 **after**；讲“从哪点进去”时对 **before** 取景。详见 steps↔camera 映射。

## 动作分级（取证边界）

| 级别 | 允许演示到 | 禁止 |
|---|---|---|
| 浏览 `browse` | 打开页面、滚动、查看结果 | 编造未打开的页面 |
| 创建 `create` | 创建到可见结果 | 用候选库冒充刚创建 |
| 编辑 `edit` | 修改到保存/可见变化 | 伪造未改动的前后对比 |
| 删除取消 `delete_cancel` | **只到确认框，然后取消** | 真正删除生产数据 |
| 支付止步 `pay_stop` | **只到收银台/支付页** | 提交支付、录入完整支付凭证 |

SPA 跳转、登录墙、二次验证：在 `note`/`evidence` 写清实际卡点与绕过方式（测试账号、已登录会话等）；不能假装无墙。细则可记在项目备注，不恢复录屏。

在项目 `script-plan.md` 与 `steps.json` 对齐后，可用[镜头表](../assets/teaching-storyboard.md)把旁白时间、观众任务、证据来源、焦点、进入/退出构图和切换理由落到制作方表格。普通短任务可写成简短对应清单。制作方填写，不能让用户填表。

讲入口时保留定位所需的菜单上下文；讲输入时近景展示实际输入和必要前置条件；讲结果时切到可核验的真实文章、图片或页面。长文字只讲关键要求，不强迫读整页。关键文字在手机观看尺寸可辨，镜头移动全程不裁半句或挡住目标。全屏使用完整画布，但横向复杂界面可以保留必要周边或分两个相连镜头；不要为铺满画面牺牲内容。只保留一个清晰结果画面，柔化背景不用于遮挡隐私。

阶段适合多阶段教程，通常3—5个短词，不照抄软件状态。只强调当前讲解阶段，固定位置避开字幕与操作目标。截图模式不新增假鼠标、点击圈、输入动画或加载百分比；图解箭头也不能冒充软件实时运行。

专家协作段以交付物为主线：谁收到什么、做了什么、交给谁（可写在 step.`who`）。比如选题卡→正文→配图/封面→排版是可选示意，实际先后和并行关系由本次证据决定。岗位介绍可用图解，交接发生与成品效果仍需真实材料证明。不要把所有专家画成已同时执行。

连贯感来自信息接续：讲解对象或页面改变才切镜头；同一原图延续焦点和比例，避免切点跳回。远中近按定位与阅读需要选择，不强制每镜头完整推拉。稳定构图期间继续讲解，保留正常换气；禁止额外插入供阅读、抄写或截图的静默停顿，也不以持续微缩放制造运动。

渲染前先确认 `steps.json` 齐图，再查看入口、输入、真实结果和图解的代表画面（按任务适用选择），手机尺寸复核目标是否一眼可找、字幕是否遮挡、字号是否可读。代表画面合格后再检查移动起中末及转场，不用整片反复导出发现版式问题。齐图与取景自检是制作方责任；六伟过 steps 为可选门禁，不把填表推给用户。
