# 内容与真实截图

先用短提纲确定观众困惑、看完能做成什么、实际需要的输入/步骤及结果证据；随后真实操作一次，把步骤写入 `steps.json`（`do`/`see`/before+after/`evidence`），核验齐图后才定稿旁白。沿用符合用户最新要求的指定开头和脚本，不让策划变成先录一堆图再找选题，也不让长旁白先锁死未验证的结果。字段与门禁见[steps-schema](steps-schema.md)。

每张截图记录：原文件、截图时间、所处页面、已做动作、可见结果、能支持哪句解说（汇总进 step.`evidence`）。**核心操作默认 before+after 成对**；模态/下拉另加一张。任务完成、候选结果、浏览器预览、微信模拟器、真机和发布状态分别表达，不能从截图推断没做过的步骤。数值以本次可见结果为准，不能复用昨天案例的72位专家、91秒或3.24积分作为新片实测。禁止用 AI 生成软件界面填补缺图。

### 动作分级（与 steps.`action_level` 一致）

- 浏览 / 创建 / 编辑：可演示到真实可见结果。
- **删除**：只演示到确认框，然后取消，不真删。
- **支付**：只演示到收银台/支付页，不提交支付。

一屏讲一个重点。入口（before）告诉观众从哪里开始；关键输入可读，示例输入与本次真实输入区分；结果（after）让人学会检查是否做成。专家团已配置时讲清前置条件，用户指定“今日热点”就以真实四字输入为证据，不把后台制作规范塞进观众输入。

按本次内容选择开头、步骤、结果、易错点和结尾，不强制每条同样镜头数量。对整段生成的实际声音进行字幕对齐，再安排截图展示时长；静态截图可以伴随持续讲解、缩放和高亮，不需要伪造实时加载来撑旁白。开头已有结果可先展示，随后回到步骤，不虚构发生顺序或效果。旁白定稿与 fullscreen 渲染前 steps 必须齐图，缺图即阻塞。

默认结尾取assets/closing.txt；本条有最新原文时统一替换。结尾金额是用户再次确认的2693元；配音输入、文案及字幕全部写阿拉伯数字666、2693，品牌统一写WorkBuddy，不改写成中文数字。预留实际说完时间，不硬塞最后几帧或暗中删结尾。

script-plan.md先写清目标观众、具体麻烦、可兑现收益、封面短标题、发布标题、开口第一句及其证据画面；实操后以 `steps.json` 为权威步骤表（可另附简短对应表：讲解重点｜实际动作/输入｜before/after｜圈框目标与对应旁白时间｜实际核验/来源）。制作方填写，不交给用户。定稿narration.txt使用长段自然口语或按短视频需要分句。保存初稿和重要修订来源，不修改原有知识库内部原文。


涉及 Skill 的选题，策划与实操先遵循[Skill查找与实操记录](skill-practice.md)：自研优先，其次 SkillHub，两处都没有合适的才开发。脚本必须对应实际选择、调用与结果；新开发的关键过程及验证不能从教学中省略。完整来源与过程保存在项目 `skill-practice.md`。

## 封面与连续讲解

**画幅**：交片封面固定 **3:4（1080×1440）整幅撑满**，禁止直接截 16:9 正文帧。封面主文案只保留一个可兑现的核心利益，采用“自动化公众号”“自动化剪辑视频”“一句话做PPT”这类短表达。小号“WorkBuddy实操”作为系列标签；不再增加步骤串、功能串、长说明和“新手一步一步跟做”等副标题。完整课题名称与跟做细节放交付说明，生成封面时明确限制为系列标签＋短主标题，检查成图有没有擅自加字。

脚本从开头到结果连续推进，不安排观众暂停阅读、截图或抄写，也不口播这种要求。遇到长文字，讲清关键要求并用近景对应；完整可复制输入放随附文案。示例：“这里告诉它三件事：按顺序拼接、每段保留四秒、加半秒转场。”说完自然接到执行和结果，不接“暂停把这段话抄下来”。

剪辑保留正常换气和理解时间，截图展示期间旁白继续解释相关内容，不添加读屏专用的无声停留或倒计时。“一气呵成”不等于提速到听不清，也不要求为了动而不停切换截图。生成配音前先检查旁白中是否含暂停阅读类话术；导出前同时检查实际时间线上有没有这种停顿。

## 标题与开头：让观众想看，并尽早看到证据

从本次已验证的用途提炼吸引点：省掉一个麻烦动作、解决一个具体难题、展示一个可见变化。少量候选在内部比较后选定一组，不让用户每条都选标题。判断标准是“目标观众是否马上知道与自己有关、想知道怎么做、实际演示能否兑现”，不编造所谓必爆分数，不承诺算法偏好或固定流量提升。

封面、发布标题、开头各有任务，指向同一个结果。封面用几个字概括利益；发布标题可补任务对象或具体变化；开头先指出具体痛点，再说本条视频带来的利益和好处，配本次真实结果画面，再自然回到步骤。时间通常参考3—10秒，依总片长和内容形式灵活调整，不设为机械硬限。没有实际结果的惊叹、“震惊”“颠覆”“再也不用请人”、虚构省时倍数和“零基础一键全自动赚钱”都不作为吸引力来源。若标题说“一句话”，应说明材料与已有配置，不把多轮纠错藏起来装成一步完成。

以下是基于已跑通的五段视频混剪案例的写法示例，可借结构，不可把案例数字挪到其他任务：

- 封面：自动化剪辑视频。
- 发布标题：五段视频自动拼成一条，哪段太长，接着说一句就能改。
- 开头：剪视频，还在一段段拖时间线？用WorkBuddy，讲清顺序和时长，素材自动拼成一条，还能一句话修改。
- 首个证据画面：播放本次实际剪出的成片，直观看见片段顺序和转场，再进入安装、素材位置与剪辑要求。短开头需要压缩播放时清楚标注预览倍速；不把倍速当实际制作效率。完成提示、结果清单、任务表格、聊天记录或文件名都不能替代成品播放。

## 正文与信任：让新手明白怎么做、为什么这样做

内容应覆盖这条任务真正需要的“准备什么、关键怎么做、结果怎么验”。每个关键动作尽量连同目的或判断标准一起讲，例如先给文件编号是为了固定顺序、另存第二版是为了保留比较。无需逐个念无关按钮，也不为了显得详细重复说明或罗列所有故障。

隐藏成本与前置条件按影响交代：预装技能、已有工具、需登录/付费或需要人工修改时，不能说成任意新账号开箱即可复现。不是每条都做免责声明；只在相关步骤讲会改变观众做法的事实。遇到失败，解决后再演示或明确功能边界，不伪造成一次成功，也不把排错过程全部塞进正文。

语气像袁六伟给初学者认真示范：有把握的说清楚，没验证的说清边界。专业感来自具体选择、检查与真实作品；不补造自我介绍、客户案例或成交成绩。观众不暂停也能沿着讲解理解动作与结果，完整输入仍放配套文案。

## 动态PPT与真实工具画面的分工

概念、总览、流程和总结可用红白动态PPT（或可选 Remotion 概念图解）解释，制作细则见[动态PPT](dynamic-ppt.md)。关键输入、真实操作与实际结果继续用原始真实截图推拉证明，图解不能替代 before/after。先按旁白决定哪些段落需要图解，再安排逐项出现与连线展开，不为了凑动画遮掉工具证据。

## 结尾与复盘：承接本条需求

先让观众得到标题承诺的结果与方法，再用已确认结尾引导一个动作。若需要加一句衔接，只说明已经实际整理好的材料怎样帮助复现本条任务；不要用无关大礼包遮住内容价值，不暗示未核实的福利包含本条素材，也不再叠加关注、私信、加群、购买等多个要求。现有指定结尾及金额不因“优化成交”擅自改写或加码。用户要求严格保留所给正文时，保留正文总结，再追加既有默认福利结尾；除非用户明确取消或提供替代结尾。不要因所贴正文没包含福利文案就推断默认已被撤销。结尾须实际进入配音、烧录字幕和最终视频，导出前后各核对一次。

有真实反馈时，分别看标题/开头是否吸引到目标观众、关键步骤是否引起疑问、领取或咨询是否与本条任务相关，再决定改哪里。记录发布条件和数据口径；无数据时只提出可验证的改进假设，不宣布已经带来流量或成交。

## 全片语速一致

开头、正文、结尾使用同一自然讲解节奏，用户最新确认当前默认全片统一1.35倍速。若旧正文曾用0.9倍而补录用1.35倍，应将正文一起校准至1.35倍，不只宣称补录倍率正确。新增或补录段落须与相邻正文对比后确定速度，不沿用生成工具默认倍率直接拼接；若用户最新指定全片1.35倍，则旧正文也同步校准，不能继续匹配旧的慢速。3—10秒只是开头参考，不以局部加速换取时长。速度修改后按真实速度变化重排字幕与画面，成果预览的倍速标签也要相应更新。检查两个连接处有没有突然赶话或明显拖慢；相同倍率不等于实际听感已经通过。
