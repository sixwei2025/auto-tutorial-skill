# Skill 查找、开发与实操记录

所有教程必须有本次真实操作、输入和可见结果。涉及 Skill 时依次执行以下分支，找到适用且经验证的能力后即可使用，不为凑开发过程重复造已有技能。

1. **先查自研。** 检查 WorkBuddy 已安装的自定义技能、`~/.workbuddy/skills`，并按选题检索已有自研资产（如 `~/.agents/skills`、`~/.codex/skills` 及 Obsidian 项目资料）。目录中的技能不自动等于自研；读取来源、内容、版本与依赖，核实是否为我们开发、是否适合本题、是否已在目标应用可调用。未安装不等于不存在。找到合适自研技能后优先复用，必要时修复或补齐，不跳到市场替换。
2. **再查 SkillHub。** 自研无合适能力时，在 WorkBuddy 的 SkillHub 入口或实际可用的 SkillHub 搜索渠道检索。记录关键词、候选、来源、能力和选择理由。普通“推荐”列表不能自动当作已经查过 SkillHub；两者来源需分清。取得合适技能后检查规则与必要依赖，按现有授权配置并真实调用。第三方技能如实注明来源，不写成我们自研。
3. **最后开发。** 自研和 SkillHub 都没有合适技能时，在本题范围内开发可复用 Skill：明确输入、预期输出和约束，编写或修改技能，接入目标应用，用实际示例调用，检查成品，修复发现的问题并再次验证。不能只生成 SKILL.md 就称开发成功。把关键开发要求、实际文件或界面、试用、修正和最终结果纳入教程，不伪造编写、执行或成功画面。没有搜索结果、候选不适用与搜索渠道不可用分别记录；渠道不可用不能写成“没有技能”，更不能据此悄悄跳过搜索顺序。

每个项目建立 `skill-practice.md`，记录实际时间、查找位置/入口和关键词、自研候选与来源判断、SkillHub候选与来源、最终选择理由、技能名称/路径/版本、必要配置、真实输入、调用证据、结果文件或画面、核验结论、失败与修正，以及对应截图/成片时间。未进入的分支注明原因，如“已找到合适自研技能，未进入SkillHub与开发”，不虚填搜索或开发记录。

记录分两层：成片保留观众复现所需的查找/选用、关键步骤、输入和结果，实际开发时必须包含关键开发与验证过程；配套档案保存完整过程和来源。口播用“现成技能、找技能、做一个新技能、试一下结果”等新手能理解的表达。真实实操使用直接取得的关键截图；禁止连续录屏、花录及先录后抽帧，保持已确认的截图动态制作方式。不能为了短片时长或十分钟交付要求省掉关键实操证据；超时如实记账。

仅更新本规则不自动授权新视频、批量或公开发布；外部服务、安装权限和网络设置仍遵循现有授权边界。
